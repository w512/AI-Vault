# Contribution Guidelines

Thanks for helping keep AI Vault useful. Please read these notes before opening a pull request.

## What belongs here

- Resources that help developers understand AI systems or build with them: tools, frameworks, models, courses, books, papers, and high-signal blogs.
- Entries should be actively maintained or still clearly relevant. Archived repositories, dead links, and abandoned products are removed.
- Not a fit: generic productivity tools, marketing or sales automation, entertainment apps, and content that is not specifically about AI.

## Adding an entry

- Search the list first to avoid duplicates. Each resource appears exactly once, in the most specific section.
- Use the format `- [Name](https://link) - Short description ending with a period.`
- Keep the description to one sentence. Say what the resource is and why it matters, without marketing language.
- Add the entry to the end of the relevant section or subsection, unless there is an obvious ordering reason to place it elsewhere.
- Prefer the canonical URL (project homepage or main repository) over blog posts or mirrors.
- If a new section is needed, add it to the table of contents as well.

## Pull requests

- One resource per pull request is easiest to review, but small batches on the same topic are fine.
- Include a one-line rationale in the PR description if the fit is not obvious.
- Run [awesome-lint](https://github.com/sindresorhus/awesome-lint) locally if you can: `npx awesome-lint`.

## Reporting problems

Open an issue for broken links, outdated descriptions, or resources that no longer meet the criteria above.
